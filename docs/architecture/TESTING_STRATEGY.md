# Fin Nest 测试策略

版本：v0.1  
状态：测试基线，agent 写代码时必须遵守  
依据：`ARCHITECTURE.md`、`FUNCTION_BOUNDARIES.md`、`DATABASE_DESIGN.md`、`FRONTEND_ENGINEERING.md`

## 1. 测试目标

Fin Nest 的测试重点不是追求表面覆盖率，而是守住财务一致性、权限边界和前端高频交互。

优先级：

1. 后端财务一致性。
2. 权限与 token 失效。
3. 交易、账户、分类、人员等删除/归档边界。
4. 前端金额输入、筛选复用、Sheet 栈、附件预览。
5. 基础 UI 组件样板页的视觉和交互稳定。

## 2. 后端必须测试的内容

交易与账户：

- 创建支出，绑定账户时扣减余额。
- 创建收入，绑定账户时增加余额。
- 支出/收入未绑定账户时不改变余额。
- 转账同时影响转出和转入账户。
- 编辑交易时通过反向流水回滚旧影响，再应用新影响。
- 删除交易时通过反向流水回滚旧影响。
- 手动余额调整生成调整记录和账户流水。
- 可收回/需归还关联会扣减有效金额，但账户现金流按原始金额处理。
- 收入冲减可收回、支出冲减需归还会减少对应项目余额，且不能扣成负数。
- 关联金额合计不能大于交易原始金额。

权限：

- 未登录不能访问账本业务接口。
- 非账本成员不能访问账本数据。
- member 可以改别人交易，但不能删除账本。
- owner 可以审批加入申请。
- 用户通过邀请码只创建申请，不直接加入账本。
- 禁用用户后 session 立即失效。
- 吊销 session 后请求立即失败。
- service token 不能绕过 actor 用户和账本权限。

删除/归档：

- 有交易关联的分类不能删除。
- 有交易关联的人员不能删除。
- 默认人员“我”不能删除。
- 有流水的账户不能硬删，应归档。
- 删除交易时附件元数据和 MinIO 清理任务按规则处理。

自动记账和快捷记账：

- 自动记账只生成待确认记录。
- 同一规则同一 period 不重复生成待确认。
- 确认待确认记录后调用交易服务创建正式交易。
- 快捷记账直接记账必须满足必填字段。
- 快捷记账不能绕过交易服务。

初始化：

- 第一个注册用户成为管理员。
- 第一个用户注册后自动创建默认账本、owner membership、默认设置、默认人员、基础分类。
- 新建账本自动创建默认设置、默认人员、基础分类。
- 初始化逻辑幂等。

## 3. 后端测试类型

单元测试：

- 金额工具。
- 周期计算。
- 权限判断。
- DTO/schema 校验。
- 有效金额计算。

集成测试：

- 使用测试 PostgreSQL。
- 覆盖 Prisma 事务。
- 覆盖交易和账户流水。
- 覆盖 session/service token 权限。
- 覆盖默认数据初始化。

端到端 API 测试：

- 登录注册。
- 创建账本。
- 创建/编辑/删除交易。
- 账户余额调整。
- 上传附件授权。
- reminder summary 计数。

## 4. 前端必须测试的内容

组件测试：

- `AmountInput` 小数位、非法输入、micros 转换。
- `FilterSheet` 根据 fields 显示不同筛选项。
- `CategoryPicker`、`AccountPicker`、`PersonPicker` 的选择与清空。
- `MoneyText` 展示有效金额。
- `AttachmentPreview` 图片/PDF 入口和关闭回退。
- `SheetStackProvider` 多级 push/pop/clear。

页面/流程测试：

- 账单页筛选后刷新列表。
- 新增交易表单读取记账设置。
- 账户非必填时可保存无账户支出/收入。
- 账户必填时无账户不能保存。
- 快捷记账直接记账条件不满足时不能开启。
- 更多页和主 Tab 红点计数展示。

视觉回归或截图检查：

- `/__dev/ui` 在移动端宽度下不应出现明显溢出。
- 底部 Tab 不遮挡内容。
- Bottom Sheet 避开 safe area。
- 交易行文字不重叠。
- 玻璃组件可读性合格。

## 5. 前端测试类型

工具：

- Vitest：工具函数、金额、filter utils。
- React Testing Library：组件行为。
- Playwright：核心移动端流程和 `/__dev/ui` 截图检查。

Playwright 视口至少覆盖：

```txt
iPhone SE 尺寸
iPhone 15/16 常见尺寸
430px 宽移动容器
```

## 6. Agent 写代码时的最低要求

后端 agent：

- 涉及交易、账户、权限、token、初始化逻辑时，必须同步写测试。
- 涉及数据库迁移时，必须说明如何验证迁移。
- 涉及金额时，必须测试小数和 bigint/micros 边界。

前端 agent：

- 新增通用组件时，必须补 `/__dev/ui` 样板。
- 新增金额、筛选、Sheet 栈、附件预览相关逻辑时，必须写组件或工具测试。
- 新增页面时，至少覆盖 loading、empty、error、saving/disabled 状态。

## 7. 不要求 v1 覆盖的内容

v1 不覆盖：

- 导入导出。
- AI 识别和模型效果。
- 站内提醒中心。
- 原生 App。
- 多租户公开服务限流。

v1 之后实现这些功能时，必须补充对应测试策略。
